# Avatar style and identity references

Status: Done

Owner: Main coordinating agent

## Goal

Generate every photo-based Twin avatar in the polished soft 3D animated style of the supplied running character while preserving the uploaded person's identity, then keep the approved baseline as the primary identity reference for activity images.

## Context and evidence

- The browser already supports private photo upload, explicit baseline generation, candidate regeneration, approval, activity generation, selection, deletion, and cache reuse.
- Baselines currently send only the uploaded photo to `POST /v1/images/edits`; activities send the approved baseline first, and activity regeneration may send the prior activity second.
- The image model is `OPENAI_IMAGE_MODEL`, default `gpt-image-1-mini`. Provider calls use the encrypted server-held key; generated bytes remain private under `data/assets/`.
- There is no durable runtime copy of the supplied style reference. Conversation attachments and `docs/references/ui/` are not runtime dependencies.
- Existing generated assets record prompt version 2 and request low image quality.
- The worktree contains substantial pre-existing changes. This task must touch only the bounded avatar files and preserve all unrelated work.

## Constraints

- Keep API credential encryption/decryption, private storage, user ownership, approval, regeneration, activity caching, and Home/Schedule integration intact.
- The identity photo determines the person's appearance; the running reference determines style only. Never copy the reference character's face, curly hair, skin tone, or navy outfit by default.
- Keep the style asset server-only and independent of user-owned deletion.
- Do not make a live paid image call or claim visual acceptance without credentials.
- No schema, migration, public endpoint, or browser-side provider call is required.

## In scope

- A tracked server-only copy of the supplied running style reference.
- Deterministic multipart reference ordering for baseline, activity, and regeneration requests.
- The requested identity/style prompt semantics and higher image quality.
- Regression tests for prompt/reference composition and existing approval/cache behavior.
- Documentation describing the workflow.

## Non-goals

- Changing the image provider, key storage, API routes, database schema, or approval controls.
- Automatically regenerating already approved images.
- Live visual evaluation or redesigning Character Studio.
- Fixing unrelated worker, UI polling, or historical-library behavior.

## Decisions and assumptions

- Reference order is: baseline = identity photo, style reference; activity = approved baseline, style reference; regeneration = approved baseline, style reference, prior activity.
- The bundled style reference is not represented as a user-owned `avatar_asset`, so deleting user images cannot remove it and private-asset DTOs remain unchanged.
- Keep the configured model contract and default `gpt-image-1-mini`; increase generation quality from low to medium.
- Increment generated asset prompt metadata to version 3.
- Existing coded SVG fallback remains unchanged.

## Discoveries

- Read-only server trace found owner-scoped asset loading and multipart ordering already suitable for the new composition.
- Read-only UI trace found that the current endpoints and controls already implement the requested approval and regeneration flow; only explanatory copy needs adjustment.
- The current worktree already routes avatar execution through the provided store, which allows credential-free worker tests without changing the browser or persistence contracts.

## Risks and recovery

- Risk: The packaged style asset is missing at runtime.
- Safeguard or rollback: Resolve it relative to the worker module and fail before a provider call with a stable local error; retaining the prior prompt-only behavior is not acceptable because it silently loses the requested style anchor.
- Risk: Style reference identity bleeds into users.
- Safeguard or rollback: Make the uploaded/approved image the first identity authority and explicitly forbid copying the style character's identity, hair, skin, body, or clothing.
- Risk: New prompt changes old approved art.
- Safeguard or rollback: Generation remains explicit and cache-aware; no existing approved asset is regenerated automatically.
